# 完成验收

完成声明必须与证据匹配。对照用户目标检查真实执行路径，不能只看 diff 或通过的测试数量。根据风险和未决问题决定验证深度。

## 核验结果

- 从用户请求和项目上下文恢复已约定的结果、相关既有行为和范围，不新增未经要求的验收条件。
- 将重要需求追到真实调用方、入口或可观察结果。孤立测试通过，不代表迁移已接入产品。
- 选择能暴露相关失败的检查：针对性测试、类型检查、构建、CLI/API 探测或浏览器交互。复用仍然有效的证据，不为走流程重复检查。
- 区分通过、失败、受阻和未执行。区分环境失败与产品失败，但不能因此认定未测试的行为正确。
- 修改后重跑证据可能失效的检查；发现新风险或失败时，再扩大验证范围。

## 按价值启用独立审查

跨模块契约、迁移覆盖、重要副作用或实现者可能遗漏的具体风险，适合交给独立 Agent 审查。任务非平凡不等于必须派发，仍须遵守运行环境的委派权限。

向审查者提供原始目标、目标工作区与版本、未提交改动范围、相关路径及必要约束。既有验证结果仅作上下文，不作为要求其背书的结论。让审查者追踪真实路径并尝试构造反例。

可选用 [QA 简报模板](references/qa-brief-template.md)；简短消息足够时，不额外写文档。

审查者应分别报告：

- **新增发现**：有证据支持的需求遗漏或回归，并给出修正方向。
- **复验内容**：独立复现了哪些已有检查，覆盖范围是什么。
- **未知事项**：缺失的证据或无法访问的环境，不把它们当作已证实的缺陷。

审查未发现问题，只代表已检查范围内没有可执行的发现，不能认证整个实现正确。审查中断或不可用时，如实披露并继续有价值的已授权验证；不编造结论，也不为获得 PASS 标签反复调用 Agent。

## UI 验证与人工审核

Agent 可以验证可测的 UI 行为，包括交互、导航、校验、状态变化、响应式行为和无障碍。用户审核证据，并对呈现、体验和产品取舍保留最终判断权。

- **UI 验证必须截图留证，供用户人工审核。** 覆盖相关状态与可观察的操作结果，说明每张截图证明了什么。
- 动态交互提供操作前后截图；必要时补录屏或日志。单张截图不能证明完整交互，日志或测试结果也不能替代必需的截图。
- 标明测试页面及相关视口、浏览器环境。证据放在项目已有的证据目录；短期审核可使用本地临时目录，并提供可点击路径。保留证据供审核，未经授权不上传或公开。
- 无法截图时，明确报告 UI 证据缺口，不能宣称已满足 UI 验证要求。
- 区分**Agent 验证通过**与**用户已人工审核通过**。完成已授权工作并准备证据后，人工审核保持待定，直到用户明确审核；不能根据自动检查或截图自行推断批准。

## 闭环处理

根据原始目标和实际证据评估发现。在已授权范围内修复有依据的问题，并验证受影响的行为。FAIL 标签或问题清单不能成为停止仍可完成工作的理由。

只有真实阻塞、需要用户决定的重要选择、授权边界或适用的项目规则要求时，才暂停请求用户输入。重复尝试不再产生有效证据时，重新考虑假设或方法，不机械重跑同一套检查。处理发现时不顺带加入无关改进。

## 按需汇报

说明验证了什么、新增发现及其处理结果、剩余限制。当测试、类型检查、运行时检查、静态审查和人工 UI 审核的状态不同时，分别说明。总体 PASS/FAIL 标签可选，不能掩盖失败或未验证的要求。

UI 工作附截图链接和人工审核状态；其他工作简要说明结果和最有力的证据即可。沿用既有授权与项目规则，本 Skill 不新增通用审批门槛、强制文档或自动发布步骤。
